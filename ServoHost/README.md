# STM32 舵机控制上位机（PyCharm 工程）

本目录是用 **Python + PyCharm** 编写的上位机程序，通过串口向下位机 STM32 发送命令，
控制接在 STM32 上的"德晟串口总线智能舵机协议 v4.01"智能舵机（如 SCS 系列）。

## 一、系统结构

```
┌──────────┐  USB转TTL   ┌───────────────┐   PA9 单线半双工  ┌──────────┐
│ 电脑上位机 │ ──────────> │ STM32F103     │ ─────────────────> │ 智能舵机  │
│ (本程序)  │ <────────── │ (改版 main.c) │   德晟 v4.01 协议  │ (ID=1)   │
└──────────┘  USART2      └───────────────┘                    └──────────┘
              PA2/PA3      USART1 (PA9)
```

上位机（电脑）与下位机（STM32）之间使用 **文本命令协议**；
STM32 与舵机之间继续沿用原工程的 `Servo.c`（德晟 v4.01 协议），**未做改动**。

## 三、下位机（STM32）改动说明

原程序只有"上电自动小摆演示"，没有接收电脑命令的通道。
为了让上位机能够控制它，`main.c` 做了如下改动（其余文件未动）：

1. 新增 **USART2（PA2=TX，PA3=RX，115200-8-N-1）** 作为与电脑通信的串口；
2. 上电仍先执行原演示（ID=1 舵机 150°~161° 小摆）；
3. 收到任意上位机命令后自动进入"手动模式"停止演示，发送 `DEMO` 可恢复演示；
4. 每收到一条命令，板上 LED（PB10）闪烁一次；手动模式下 LED 常亮。

**重新编译烧录步骤（Keil）：**

1. 用 Keil 打开工程 `GCWJ\GCWJ.1.uvprojx`；
2. 确认工程中编译的是 `User\main.c`（`main_original_demo.c` 不要加入工程）；
3. Rebuild 后用原来的方式烧录（ST-Link / 串口 ISP 均可）；
4. 烧录后打开上位机，上电 1 秒内会收到下位机问候：
   `READY STM32F103 SERVO HOST V1.0`。

> 注意：原 `main.c` 上电会广播把舵机 ID 设为 1。若你以后接多个舵机，
> 请删除 `Servo_SetID(1)` 这一行，改用上位机的"设置舵机ID"逐个设置。

## 四、接线

### 模式 A：STM32 上位模式（默认，推荐）

| USB-TTL 模块 | STM32 引脚 | 说明 |
|---|---|---|
| TX | PA3 | USART2 接收 |
| RX | PA2 | USART2 发送 |
| GND | GND | **必须共地** |

- 舵机数据线仍然接 **PA9**（原工程接法不变）；
- 舵机电源用外部电源（5V 或 6~8.4V，按舵机型号），**不要**用 USB-TTL 的 3.3V/5V 给舵机供电；
- USB-TTL 与 STM32 都是 3.3V 电平可直接接；5V 电平的 USB-TTL 请确认板子容忍度。

### 模式 B：直连舵机模式（无需重新烧录下位机）

把 USB-TTL 的 **TX 与 RX 并联**后接到舵机数据线，GND 与舵机电源共地。
此时上位机直接发送德晟 v4.01 协议帧驱动舵机（程序会自动过滤自发回显）。

## 五、PyCharm 运行步骤

1. 打开 PyCharm → `File → Open`，选择本目录 `ServoHost`；
2. 配置解释器（Python 3.8 及以上）：`File → Settings → Project → Python Interpreter`，
   建议新建虚拟环境 venv；
3. 安装依赖（PyCharm 底部 `Terminal` 中执行）：
   ```bash
   pip install -r requirements.txt
   ```
4. 右键 `servo_host_gui.py` → `Run 'servo_host_gui'`；
5. 界面操作顺序：
   1. 选择工作模式（默认"STM32 上位模式"）；
   2. 点 **刷新** 选串口（如 COM3），点 **连接**；
   3. 填好 舵机ID / 满行程角度 / 目标角度 / 运行时间；
   4. 点 **移动到目标角度**、**读取当前位置**、**PING 检测舵机** 等按钮；
   5. 所有收发内容显示在下方日志区。

> 无硬件自检：`python _smoke_test.py` 会用伪造串口把整个程序逻辑跑一遍
> （连接、命令发送、协议组帧、应答解析），全部通过会打印 `ALL TESTS PASSED`。

## 六、命令协议（STM32 上位模式）

文本行，`\r\n` 结尾，大小写不敏感，参数空格分开（角度可带小数）：

| 命令 | 参数 | 功能 | 应答示例 |
|---|---|---|---|
| `PING` | id | 检测舵机是否在线 | `OK PING 1` / `ERR PING 1` |
| `MOVE` | id 角度° 时间ms | 按角度转动 | `OK MOVE 1 2048` |
| `MOVEP` | id 位置0~4095 时间ms | 按原始位置转动 | `OK MOVEP 1` |
| `READ` | id | 读当前位置 | `POS 1 2048` / `ERR READ 1` |
| `SETID` | id | 广播改舵机ID（掉电保存） | `OK SETID 1` |
| `RANGE` | 角度° | 改满行程角度 180/270/300/360 | `OK RANGE 300` |
| `RESET` | id | 复位舵机 | `OK RESET 1` |
| `DEMO` | 无 | 恢复上电演示摆动 | `OK DEMO` |
| `HELP` | 无 | 打印帮助 | 命令列表 |

角度 ↔ 位置换算（固件和上位机一致）：
`位置 = 角度 × 4095 ÷ 满行程角度`（满行程默认 300°，可在上位机"满行程角度"框修改）。

## 七、常见问题

1. **连不上串口**：确认驱动（CH340/CP2102）已装；串口被其他软件占用时先关掉；
2. **连接成功但舵机不动**：
   - 确认已烧录改版后的 `main.c`（收到 `READY` 问候才算成功）；
   - 检查舵机供电（舵机没电或供电不足最常见）；
   - 检查舵机数据线接 PA9、与舵机共地；
   - 点"PING 检测舵机"看是否在线；
3. **舵机乱动/角度不对**：检查"满行程角度"是否与舵机型号一致（300°/270°/180°）；
4. **直连模式无应答**：确认 TX、RX 已并联接数据线、共地、舵机已上电；
5. **上电后舵机自己摆动**：那是下位机的演示模式，发一条 `MOVE` 或点"恢复演示"外的任意按钮
   即进入手动模式停止演示；
6. **恢复出厂演示**：发送 `DEMO`。
