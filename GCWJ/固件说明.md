# GCWJ 固件说明（DOFBOT Pro 机械臂 / 德晟总线舵机 v4.01）

## 1. 这份固件做什么

STM32F103C8 插在电脑和总线舵机之间，扮演"实时舵机控制器"：

* 从**电脑**（USB-TTL，USART2 PA2/PA3）收二进制帧：6 个舵机目标位置；
* 在**内部**做软限位 → 角速度限速 → 软启动；
* 每 20ms 用**一帧 `SYNC WRITE(0x83)`** 把 6 个舵机同时写下去（USART1 PA9 单线半双工）；
* 回传状态帧（当前指令位置 + 舵机回读位置），供 ROS 侧发布 `/joint_states`；
* 同时保留原来的**文本命令**，老版 `ServoHost` 上位机仍可用。

上电后**不会自己动**，必须收到上位机命令，这是安全设计。

## 4. 主要参数（`robot_config.h`）

```c
#define ARM_SERVO_IDS      { 1,2,3,4,5,6 }   // 关节 1..6 的舵机 ID
#define ARM_HOME_TICKS     { 2047,... }      // 回中位的位置
#define ARM_TICK_MIN/MAX   { ... }           // 上电默认软限位
#define ARM_MAX_DPS        { 240U,200U,... } // 每关节限速（度/秒）
#define ARM_SERVO_WIRING     2              // 0=双线PA9/PA10 1=单线PA10 2=单线PA9(默认)
#define ARM_SERVO_PERIOD_MS  20              // 20ms = 50Hz
#define ARM_BUS_MODE         0              // 0=SYNC WRITE,1=逐个写,2=REG+ACTION
#define ARM_SERVO_RANGE_DEG  300            // 舵机满行程角度
#define ARM_LINK_TIMEOUT_MS  400            // 电脑失联保护
#define ARM_SOFTSTART_MS     400            // 进入跟随后前 400ms 步长减半
#define ARM_READBACK_ENABLE  1              // 回读真实位置（供 /joint_states）
#define ARM_READBACK_DIV     5              // 每 5 个周期读一个舵机
#define ARM_TELEM_RATE_HZ    0              // 状态帧默认关(老上位机不刷屏)，ROS 侧会自动打开
#define ARM_LINK_BAUD        115200         // 电脑↔STM32
#define ARM_SERVO_BAUD       115200         // STM32↔舵机总线
```

## 5. 通信协议

完整定义见 `User/robot_link.h` 注释。摘要：

```
帧：  AA 55 | CMD | SEQ | LEN | PAYLOAD | CRC_H CRC_L
CRC： CRC16-CCITT（初值 0xFFFF，多项式 0x1021），覆盖 CMD/SEQ/LEN/PAYLOAD
```

| CMD | 负载 | 说明 |
|---|---|---|
| 0x01 | – | PING → `0x81 PONG {verH,verL,njoint,busmode}` |
| 0x02 | 6×int16 BE | 6 个目标位置 0~4095 |
| 0x03 | u8 | 0=保持 1=跟随 2=回中 |
| 0x04 | u16 BE | 回中位用时（ms） |
| 0x05 | 12×u16 BE | 6 下限 + 6 上限（软限位） |
| 0x06 | – | 读位置 → `0x84 POS 6×u16` |
| 0x07 | u8 | 状态帧频率 Hz（0=关） |
| 0x08 | – | 停止（保持当前位置） |
| 0x09 | – | 请求状态帧 |
| 0x0A | u8 | 总线下发方式 0/1/2 |
| 0x82 | `{cmd,result}` | ACK，result：0 OK / 1 未知指令 / 2 长度错 / 3 忙 / 4 超范围 |
| 0x83 | `{flags,mode,6×u16 cmd,6×u16 meas}` | 状态帧（26 字节） |

`flags`：bit0 跟随中、bit1 曾超时、bit2 有限位钳位、bit3 回读失败。

## 6. 文本命令（兼容旧 ServoHost 上位机）

固件会自动区分"二进制帧"和"文本行"（收到 0xAA 当作二进制，否则当文本；
线路静默 200ms 后可重新判定）。

```
PING id                READ id              SETID id
MOVE id 角度 时间ms     MOVEP id 位置 时间ms   RANGE 角度
RESET id               HOME [ms]            JOINTS            TELEM hz
STREAM 0|1             BUSMODE 0|1|2        WIRING 0|1|2      HELP
```

> 与旧固件的差别：**不再上电广播 `SETID 1`**（以前会把所有舵机改成同一个 ID），
> **不再上电演示摆动**，开机问候语改为 `READY STM32F103 ARM BRIDGE V2.0`。

## 6.1 舵机总线接法（WIRING）

| 值 | 接法 | 用在 |
|---|---|---|
| 0 | 双线：PA9=TX、PA10=RX | 经驱动板 UART 口（TX/RX 两根线） |
| 1 | 单线半双工，只用 PA10 | 特殊转接板 |
| 2 | 单线半双工，只用 **PA9** | **默认**：PA9 直接接舵机数据线（不经驱动板 UART） |

运行时可发 `WIRING 0|1|2` 切换，不用重烧。

## 7. 诊断

* 板载 LED（PB10）：500ms 慢闪 = 正常运行；常亮 = 正在跟随轨迹。
* 调试器里可看 `g_diag`（`Servo.h` 的 `Diag_t`）：
  `magic=0xD1A60002`、`tickMs` 心跳、`txBytes/rxBytes`、`syncWrites`、
  `ackFail`、`phase=3`（PA9 半双工 115200）。
* 用 `servo_tool monitor` 看状态帧；用 `servo_tool --fake` 验证电脑侧代码。

## 8. 总线时序（为什么是 50Hz）

* 一帧 `SYNC WRITE` 写 6 个舵机 = 38 字节 ≈ 3.3ms @115200；
* 加上偶发应答与位置回读（每 5 个周期读 1 个舵机，最多 3ms）；
* 20ms 周期下总线占用约 20~35%，留足余量；舵机内部按"运行时间 25ms"做插值，
  相邻两帧之间不会停顿，动作连续。

如果把 `ARM_SERVO_PERIOD_MS` 改成 10（100Hz），请同时把上位机
`arm_calib.yaml` 的 `command_rate` 改成 100，并注意总线占用会翻倍。
